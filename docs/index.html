Obelus

A terminal code reader.
It doesn't want you to type.

In the AI era every line you read is a line you did not write. An obelus (÷, †) is the mark a scholar put in a manuscript's margin to flag a line as doubtful — a reader's mark, made while reading.

Get started Read the principles GitHub

01Why it exists

Honestly: it was written for me first. Every trade-off answers "does this work for me" before it answers "will somebody else refuse to use it without feature X".

I never got comfortable with the way vim is used. Modes, hjkl, colon commands — muscle memory for the people who have it, and for me something to work out again every time I open a terminal. What I wanted was: open it and read. Arrow keys are arrow keys, Ctrl+c copies, and nothing has to be escaped out of first.

The other half is that reading code has genuinely changed. A lot of the lines are written by something else now, and what I do in front of a terminal is read, check, mark what looks doubtful, and ask an agent about it — rather than type. There are good editors in a terminal, but they are editors: the feature list is an editor's list, with multiple cursors and macros and snippets on it. What I wanted sits on another line entirely — the syntax tree, the git timeline, the language server and the agent, all organised around reading.

How I actually work

Working with AI, I usually have several projects going at once: a pile of claude code and codex sessions, an editor, and a todo list for planning what comes next. I also keep several worktrees of one repository, each carrying a different part of the work. Obelus is shaped for that: it does not split, and assumes instead that you are running several, which it is prepared for.

That todo list is also why the notes are in Obelus at all: planning the next step happens in the middle of reading code, not in another application.

03Principles

These are not slogans written afterwards. They are the sentences the trade-offs actually get decided against, and most of them were written down after getting it wrong once.

  1. 01

    Reading is the product; editing is incidental.

    Called an editor, it gets measured by an editor's checklist — multiple cursors? macros? snippets? — none of which it wants. There is basic editing, for the line you fix on the way past.

  2. 02

    No dialect to learn first.

    No modes. Arrow keys are arrow keys, Ctrl+c copies, Ctrl+z undoes. What your hands already know from a graphical editor works here.

  3. 03

    No splits.

    Two files side by side is another Obelus. This is settled rather than not got to yet — which is why running several at once is the normal case, and prepared for: see many windows, many worktrees.

  4. 04

    A change that has happened is in the file; one that is still being asked for is in the conversation.

    Once an agent has edited a file, that is the difference between the working tree and the last commit, and the margin already draws it; drawing it again in the transcript would be a second account of one thing. What it is asking to do goes in the transcript, and stays there.

  5. 05

    A file being rewritten while you read it is the normal case.

    Not the exceptional one — an agent edits the file you have open, a formatter runs, a branch changes underneath you. So Obelus re-reads by itself rather than asking, and without losing your place; a file that has gone away is marked [stale] and keeps its contents on screen.

04What it does

Reading a file

  • Syntax highlighting, fifteen languages
  • gutter, soft wrap, folding (Alt+f)
  • Long lines break by the Unicode line breaking algorithm: Chinese breaks between characters, an English word is not cut in half, continuation rows keep the indentation
  • One file, more than one reading: markdown laid out as prose (Ctrl+t), a log put in columns — decided by what the lines look like, not by the file's name
  • One file, more than one language: the code in a markdown fence and the script in an HTML page are each highlighted as what they are

git

  • Change marks in the margin, saying what git diff says
  • A map of the file's changes just inside the scrollbar
  • Alt+d opens a hunk in place; Alt+p / Alt+n step between changes
  • Who last changed the line, in the margin (switchable)
  • The file's history F9, the project's F10, the commit that wrote this line F11; a commit's message hangs above its file, and what the remote has not seen is marked
  • Read-only: Obelus never changes your repository, and runs no git for you

Language servers

  • Definition F12, outline F7, symbol search F8
  • Alt+Enter opens the menu about the name under the cursor: type definition, implementations, references, calls
  • Hover Alt+h, or by resting the pointer (the delay is a setting; zero is off)
  • Diagnostics: all of them Alt+e, previous and next Alt+[ Alt+] — and a server is not the only thing that makes one: what Obelus cannot make of a file it reads for its own sake is marked on the line it could not read
  • Rename Alt+r, code actions Alt+a, inlay hints (switchable — off puts every column back where the file has it)
  • Known servers: rust-analyzer, gopls, clangd, pylsp, typescript-language-server, bash-language-server, CSS / HTML / YAML

In a terminal, or in a window

  • ob is the terminal and obg is a window — gvim's relation to vim, not a second program: the same grid, the same views, the same keys
  • The window is for the two things a terminal cannot give. It cannot tell Ctrl+i from Tab, Ctrl+m from Enter or Ctrl+[ from Esc — one byte each — and most send nothing at all for Ctrl+Shift+X
  • And it draws with a font it carries rather than one it hopes you installed: the marks are compiled in, so there are no boxes and no switch to find
  • It draws its own pixels, so the caret's shape says what the next key will do, the caret and the lists move rather than jump, and what an input method is spelling is on the page before it is a character
  • A setting says where it applies: fonts, font_size and animation mean nothing in a terminal and icons means nothing in a window, so the page shows the ones that apply — and the file keeps them all, because the other Obelus on that machine is the one they are for

Finding things

  • One view at three radii: this file F5, every file F6, symbols F8
  • Files, open documents, themes and commands: four lists that work the same way
  • While results are still arriving the list does not jump about, and says that it is still reading
  • Alt+← / Alt+→ go back to where a jump was made from, and undo that

05Getting started

Install

From source, for now. It needs a recent Rust toolchain (edition 2024).

git clone https://github.com/sunli829/obelus
cd obelus

# installs as `ob` into ~/.cargo/bin
cargo install --path crates/obelus-cli

# installs as `obg`: the same reader, in a window of its own
cargo install --path crates/obelus-gui

# or just build them: target/release/ob and target/release/obg
cargo build --release

Optional, but worth having:

  • A Nerd Font, for the glyphs beside a file's name and on the status bar — in the terminal. They are off until icons is turned on, so without one no boxes appear. obg needs none of this: it carries the marks in the binary.
  • A language server for your language (rust-analyzer for Rust). Without one, reading still works — there is just no definition, no diagnostics, no outline.
  • An ACP agent. Obelus can install one from the registry — see below.

Run it

ob                   # nothing: the welcome screen, on this directory
ob src/main.rs       # read a file — its repository is the project
ob ../another-repo   # a directory: that is the project
obg src/main.rs      # the same file, in a window instead

The first five minutes

  1. F1 opens a file. Type to narrow, ↑↓ to choose, Enter to accept, Esc to cancel.
  2. Not sure which keys a view takes? Press Ctrl+k. The row at the foot lists what is available now; Ctrl+k opens all of them, with the rest greyed out.
  3. Ctrl+p is the command palette: anything you cannot remember a key for is findable by name.
  4. Put the cursor on a change and press Alt+d: the hunk opens in place, with what was there before it.
  5. See a line you doubt: Alt+t, and write a sentence. It goes in this project's notes, and todo brings them all back.
  6. Ctrl+p → open-settings for colours, wrapping, tab width; choose-theme for the theme.
  7. Ctrl+q leaves.

And one key that is none of the three

Insert is toggle-replace: type over what is under the cursor instead of before it. Bare, and outside the families above, because that is what the key is called on every keyboard that has it. The caret changes shape to say so — a block stands on a character and says the next one takes its place — and the status row says Replacing in a word as well, because a terminal's caret is the terminal's and only a window can draw the other half.

Moving, and inside a list

Navigation is not a command, so it is not in the tables above: the arrows, PageUp/PageDown, Home/End for the line's ends, Ctrl+Home/Ctrl+End for the file's. Up and down move by visual row, so a wrapped line still moves the way it looks. Shift never names a command: it only ever extends.

Inside a list — any picker, the settings, the counts, the notes — type to narrow, ↑↓ to choose, PageUp/PageDown to cover ground, Home/End for either end, Enter acts on the row you are on, Esc cancels, and Ctrl+k lists every key. A function key works from inside a whole-screen view as well, and goes to the view it names in place of the one showing — F6 from the files is the search, F3 is the files' other tab.

08Config & themes

Two files

FileWhose
~/.config/obelus/config.tomlYours. open-settings writes it the moment anything changes
<project>/.obelus/config.tomlThe project's, laid over yours — but only for what it is allowed to set

A missing file means the defaults, and so does a line Obelus does not recognise: a typo should leave you with Obelus, not with an error message where your reader was. A file it cannot read is the one thing it treats differently — it stops writing to that file rather than saving over settings it never saw, says so, and starts again the moment the file parses.

And it tells you where. A settings file that will not parse, a key that binds nothing, a setting a project is not allowed to set, a theme named that no file answers to — each is marked on its own line, in the same list a language server's problems go in, so Alt+e and Alt+[ Alt+] walk them like any other. Obelus writes the file, so Obelus has to be able to say which line it could not read.

Three a project may not set: agent, keys and agents. A program starting because a downloaded project said so is a decision that belongs to the person at the keyboard; a project that could rebind keys could put quit where you would find it by accident; and what an agent may do without asking is the setting a downloaded project would most like to write.

The settings

A few of them belong to one front end. The settings page shows you the ones that apply where you are reading — a row you can change and watch do nothing has taught you something untrue — and the file keeps them all, because the other Obelus on that machine is the one they are for.

Rebinding

Changes rather than the whole table: rebind one key and everything you said nothing about still gets the current default. An empty chord is a key taken away, which is also a decision. The names are the command names above, and the keys are spelled the way the screen spells them — the case is not read, so a file written before they were capitalised still works.

theme = "light"
wrap = true
blame_margin = false

[keys]
open-file = "Ctrl+o"
show-change = "Alt+g"
quit = ""            # taken away

Themes

Built-in dark and light, switched by choose-theme without a reparse. Beyond those, every .toml in ~/.config/obelus/themes/ is a theme, named by the file (omarchy.toml → omarchy). Every colour is optional and whatever is not given comes from the built-in theme it builds on — which is what keeps old files working when a colour is added later.

contrib/omarchy/ in the repository is a template for omarchy, so the desktop's palette writes Obelus's theme file for you. Nothing in Obelus knows about omarchy: a theme is a file.

09Notes

An obelus is the mark a scholar put beside a line they doubted. This is that mark, written down.

Alt+t while reading opens the notes with one started against the line under the cursor; todo opens them all. The page is always being written: the caret is in it when it opens, a letter is a letter, Enter starts another note and Shift+Enter a line inside one. What acts on a note as a note is under Alt: tick it, go to what it is about, move it, take it away. The keys are along the bottom.

A note may be about a line or about the project, and both are ordinary: "this cache is wrong" belongs to a line, "wire the counts page up to the search" belongs to the project. Where it points goes on a row of its own under it, and one that says nothing is not kept. A note can hang under another; the indentation is the nesting.

A note written last week still points at what it was written about

Line numbers move. So a note keeps the commit it was written against as well as the line, and finding the place again is a question for git — rather than pointing at whatever has since moved into that line.

Where they live

In Obelus's own directory, kept per project rather than per checkout — so several worktrees of one repository open the same list. They are your notes, and they do not end up in the project's commits.

10Talking to an agent

Obelus implements nobody's model. It talks to whatever you already have, over ACP (the Agent Client Protocol) — the same shape as a language server: another program, over its own standard input and output.

Installing one

Which agents exist is not Obelus's to decide. There is a registry kept by the protocol's own authors, and Obelus reads it: forty entries with a name, a version, a description and how to install each one. F4, then the agents page, then install one. A terminal that can draw pictures gets each agent's own mark; one that cannot gets a glyph. One agent at a time — two would mean every question having to say which agent it was for, and you having to know which.

A conversation is a document

It sits in the list of open documents (F2). Leaving one is going somewhere else rather than closing it: what was said is still there when you come back. Enter sends, Alt+Enter makes a line (and Shift+Enter where the terminal reports it). The status row is the agent's own session options — mode, model, reasoning effort — walked and changed there, with Shift+Tab going the other way as it always does. Obelus translates none of them: which options exist is the agent's business.

A conversation belongs to a note

Opened with F4, a conversation is about nothing in particular. Opened from a note, it is about that note — and it stays that way: come back tomorrow and the conversation is where you left it, because the agent replays what was said and Obelus only has to remember which conversation was about which note.

Obelus tells the agent what the note says when the conversation starts. You reword the note overnight, and the next message carries what changed — nothing in the protocol would otherwise let an agent find out that a file it was told about on Monday says something else on Tuesday.

Before your first words, Obelus also says who the agent is talking to: that the person is reading code in a terminal, that what it sends lands beside the file they are reading, and that a choice which is theirs to make should be asked as a question rather than written into a reply as 1) … 2) … — because that arrives as prose, and nothing on the screen would say an answer is wanted.

When it asks you something

A question is a card, not a picker. Above it is what the agent is actually going to do — the tool call itself, in the transcript where every call goes — and below it are the answers. Walking does not choose: the box is under the answers, so every way to it walks over them, and a card whose answer followed the focus would answer with whichever row you passed on your way somewhere else. Enter acts on the row you are on, and that is the whole key table.

When it wants to change a file

A change that has been made is a row with +12 -4 on it, and the file is where it is read. A change it is asking to make is the opposite: those lines are in neither the file nor the last commit, so they go in the transcript, under the call's own row, open — and they stay there afterwards, which is how you find out later what you agreed to. Drawn the way an opened hunk is drawn in a file, because it is the same thing being said.

Obelus hands it the notes

An agent can read a file and ask permission through the protocol it is already speaking. What it cannot do that way is anything about obelus: it has no way to say "I think that note is finished" or "here are two more worth writing down". MCP is the door for that, and Obelus is the server on the other side of it. None of the tools asks you anything: the asking is the agent's to do, through the protocol it is already speaking.

ToolDoes
todo_listEvery note this project keeps: what it says, whether it is done, where it points
todo_addWrite notes down. What somebody would want to come back to, not a summary of what it just did
todo_finishTick a note off. It only ticks: a list of what was decided against is worth as much as a list of what was never got to, and taking one away is yours
todo_rewordRewrite what a note says. The one tool here that loses something — the notes are not in git and the page has no undo — so it is required to ask first, showing both what the note says now and what it would say instead

11Many windows, many worktrees

Obelus has no splits, so several Obelus on one project is not an edge case but the premise. These are the promises it makes because of it.

A repository and its worktrees are one project

Three worktrees of one repository open one set of notes, and share one record of which conversations are in use. With three of them open, you mean to come back to one list rather than three.

Two windows writing notes do not erase each other

Every change is made against what is on disk at that moment, not against what this window happened to be holding. So a note the other window just wrote does not vanish because you saved second — and being killed halfway through never leaves half a file.

A conversation is open in one Obelus at a time

The agent keeps what was said and takes one turn at a time; two windows prompting one conversation is two turns in it. So a conversation is claimed, and the other windows can see that somebody has it. The claim goes when the process goes — killed, crashed, power cut — with nothing to clean up afterwards and no "it did not exit properly last time, so now it will not open".

What another window did turns up by itself

While the notes are open, a note another window just wrote and a conversation it just opened turn up on this page by themselves, without your pressing anything first.

Before saving, it looks at what is on disk

Another window, an agent or a formatter may have changed the file since you opened it. That question is asked of disk at the moment you save, rather than guessed from whether a notification happened to arrive.
