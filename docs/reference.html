Reference

Every key, command and setting, and the tools Obelus offers an agent. What Obelus is for is on the front page.

01Keys & commands

No modes, so every key below means what it says whenever it is pressed — the VS Code and Emacs way, not the vim and helix one. Three families, and the family is the memorable part. This is the default table; every one of them can be moved — see settings.

Two banks of four, which is how they sit on the keyboard. Bare, never with a modifier: terminals disagree about what a modified function key even sends, so binding one works on this machine and not the next.

And two that are not modified

Insert is toggle-replace — type over what is under the cursor rather than before it, which the status row says in a word — and Esc stops selecting, or gives up on whatever is nearest.

Moving, and inside a list

Navigation is not a command, so it is not in the tables above: the arrows, PageUp/PageDown, Home/End for the line's ends, Ctrl+Home/Ctrl+End for the file's. Up and down move by visual row, so a wrapped line still moves the way it looks. Shift never names a command: it only ever extends — except Ctrl+Shift+w in a terminal, below.

Inside a list — any picker, the settings, the counts — type to narrow, ↑↓ to choose, PageUp/PageDown to cover ground, Home/End for either end, Enter acts on the row you are on, Esc cancels, and Ctrl+k lists every key. A function key works from inside a whole-screen view as well, and goes to the view it names in place of the one showing — F6 from the files is the search, F3 is the files' other tab.

In a conversation

Enter sends, and Alt+Enter makes a new line (so does Shift+Enter, in a terminal that reports it). → in an empty box fills in the first thing a conversation about a note offers to say. Shift+Tab walks the agent's own modes, on the row at the foot. Esc stops the agent's turn, and anything it was running with it. Alt+t goes to the note the conversation is about. A question is a card: ↑↓ to walk it, Enter on the row you are on.

On the notes page

The page is always being written: a letter is a letter, Enter starts another note, and Alt+Enter or Shift+Enter a line inside one. Tab hangs a note under the one before it and Shift+Tab brings it back out. What acts on a note as a note is under Alt: Alt+Space ticks it, Alt+o goes to the line it points at, Alt+a opens its conversation, Alt+↑Alt+↓ move it, and Alt+← takes it away.

In a terminal

open-terminal starts your shell in the project, as a document of its own; an agent that wants you signed in runs its sign-in in one the same way. While its program runs, the keys are the program's — Esc, Ctrl+c, Ctrl+w and Ctrl+q included. Obelus keeps the function keys, Ctrl+p, Shift+Insert to paste, and Ctrl+Shift+w to close it, which asks first while the program is still running. The wheel reads back up what has gone by. Once the program has ended the keys are Obelus's again, and Ctrl+w closes it like anything else.

02The agent's tools

An agent can read a file and ask permission through the protocol it already speaks. What it cannot do that way is anything about your notes, so Obelus offers it a few tools over MCP. None of them asks you anything: the asking is the agent's to do, on a card, before it calls one.

ToolDoes
todo_listEvery note this project keeps: what it says, whether it is done, where it points
todo_addWrite notes down — at the top level, or under a note, which is where the steps a conversation about that note works out go. What somebody would want to come back to, not a summary of what it just did
todo_finishTick a note off. It only ticks: a list of what was decided against is worth as much as a list of what was never got to, and taking one away is yours
todo_rewordRewrite what a note says. The one tool here that loses something — the notes are not in git and the page has no undo — so it is required to ask first, showing both what the note says now and what it would say instead

Three more: open_file puts a file on your screen at a line, once you have said yes — Alt+← brings you back; read_workflow hands the agent the workflow this project is set to when it is about to change something; and close_conversation closes the conversation it is in, once you have said yes.

03Settings & themes

Two files

FileWhose
~/.config/obelus/config.tomlYours. open-settings writes it the moment anything changes
<project>/.obelus/config.tomlThe project's, laid over yours — but only for what it is allowed to set

A missing file means the defaults, and so does a line Obelus does not recognise: a typo should leave you with Obelus, not with an error message where your editor was. A file it cannot read is the one thing it treats differently — it stops writing to that file rather than saving over settings it never saw, says so, and starts again the moment the file parses.

And it tells you where. A settings file that will not parse, a key that binds nothing, a setting a project is not allowed to set, a theme named that no file answers to — each is marked on its own line, in the same list a language server's problems go in, so Alt+e and Alt+[ Alt+] walk them like any other. Obelus writes the file, so Obelus has to be able to say which line it could not read.

Five a project may not set: agent, keys, agents, new_versions and conversation_days. A program starting because a downloaded project said so is a decision that belongs to the person at the keyboard; a project that could rebind keys could put quit where you would find it by accident; and what an agent may do without asking is the setting a downloaded project would most like to write; and whether Obelus asks the network about a newer version is yours to decide, not a downloaded project's; and a project that could shorten how long your conversations are kept would be a downloaded file emptying your list.

The settings

A few of them belong to one front end. The settings page shows you the ones that apply where you are reading — a row you can change and watch do nothing has taught you something untrue — and the file keeps them all, because the other Obelus on that machine is the one they are for.

Key Default What it is
theme"dark"The colours Obelus draws in
iconsfalseA terminal only. Nerd Font glyphs — one without a patched font draws a box instead. obg carries the marks in the binary, so it never asks
wrapfalseWhether a line too long for the screen carries onto the next row. Off, so a line is a line
blame_margintrueWho last changed the line the cursor is on
tab_width4How wide a tab is drawn. 2, 4 or 8
fonts[]A window only. The faces to draw with, in your order, each tried for the character before the next. Empty means what this machine calls monospaced — asked of the platform, not of the text engine
animationtrueA window only. Whether the caret flies to where it is going and a list slides rather than jumps. Off, everything arrives where it belongs at once
font_size14A window only. How big the text is, in points. A terminal draws with the font you gave the terminal
hover_delay400How long the pointer rests before Obelus asks what a word is, in milliseconds. Zero asks only when a key does
format_on_savefalseAsk the language server to lay the file out before writing. Off: a formatter that ran without being asked would rewrite a file somebody opened to read
code_actions_on_savefalseMake the server's whole-file fixes before writing. Off, for the reason above it
inlay_hintstrueDraw the types and parameter names a server infers. They are not in the file: turning this off puts every column back where the file has it

ignored_filesfalseWhether the file list offers the files a project has said to ignore

The agent still has it, but Obelus forgets the way back, and making this longer does not bring it back. One about a note goes when the note does, and one open in any window is kept

Rebinding

Changes rather than the whole table: rebind one key and everything you said nothing about still gets the current default. An empty chord is a key taken away, which is also a decision. The names are the command names above, and the keys are spelled the way the screen spells them — the case is not read, so a file written before they were capitalised still works.

theme = "light"
wrap = true
blame_margin = false

[keys]
open-file = "Ctrl+o"
show-change = "Alt+g"
quit = ""            # taken away

Themes

Built-in dark and light, switched by choose-theme without a reparse. Beyond those, every .toml in ~/.config/obelus/themes/ is a theme, named by the file (omarchy.toml → omarchy). Every colour is optional and whatever is not given comes from the built-in theme it builds on — which is what keeps old files working when a colour is added later.

contrib/omarchy/ in the repository is a template for omarchy, so the desktop's palette writes Obelus's theme file for you. Nothing in Obelus knows about omarchy: a theme is a file.
