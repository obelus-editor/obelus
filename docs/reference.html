Reference

Every key, command and setting, the tools Obelus gives an agent, and what happens with several windows open. What Obelus is for is on the front page.

01Keys & commands

There are no modes, so every key below does the same thing whenever you press it, like VS Code or Emacs and unlike vim or helix. The keys come in three families: function keys, Ctrl and Alt. Remember what each family is for and the rest follows. These are the defaults, and you can rebind any of them: see settings.

Function keys open something to look at

Three groups of four, the way they sit on the keyboard: F1–F4 open things to read, F5–F8 search, F9–F12 are git and go-to-definition. None of them takes a modifier, because terminals disagree about what something like Shift+F5 sends, so a binding like that works on one machine and not the next.

And two without a modifier

Insert is toggle-replace: what you type replaces the character under the cursor instead of going in front of it, and the status row says Replacing while it is on. Esc clears the selection, or closes whatever is on top.

Moving, and inside a list

Moving around isn't a command, so it isn't in the tables above: the arrow keys, PageUp/PageDown, Home/End for the start and end of a line, Ctrl+Home/Ctrl+End for the start and end of the file. Up and down go by the rows you see, so a wrapped line moves the way it looks. Shift is never a command of its own: it only extends the selection.

In any list (a picker, the settings, the line counts): type to filter, ↑↓ to pick, PageUp/PageDown to move a page, Home/End to jump to either end, Enter on the row you're on, Esc to cancel, and Ctrl+k to see every key. Function keys work inside a full-screen view too, and swap it for the view they open: F6 from the file list goes to search, and F3 is the file list's other tab.

In a conversation

Enter sends, and Alt+Enter starts a new line (Shift+Enter does too, in terminals that support it). In a conversation about a note, → in the empty box fills in a suggested first message. Shift+Tab switches between the agent's own modes, shown along the bottom. Esc stops the agent, along with any command it is running. Alt+t takes you to the note the conversation is about. When the agent asks you something, it's a card: ↑↓ to move, Enter to answer.

On the notes page

The notes page is always ready for typing: letters go straight in, Enter starts a new note, and Alt+Enter or Shift+Enter starts a new line inside one. Tab moves a note under the one above it, and Shift+Tab moves it back out. Everything else you do to a note is under Alt: Alt+Space ticks it, Alt+o goes to the line it points at, Alt+a opens its conversation, Alt+↑Alt+↓ move it, and Alt+← removes it.

In a terminal

open-terminal opens your shell in the project, as a document of its own. When an agent needs you to sign in, its sign-in runs in one of these too. While a program is running, it gets the keys, Esc and Ctrl+c included. Obelus keeps only the function keys, Ctrl+p, Ctrl+q to quit, Ctrl+v or Shift+Insert to paste, and Ctrl+w to close the terminal (it asks first if the program is still running).

To look back at output that has scrolled away, use the mouse wheel, PageUp/PageDown for a screen at a time, or Ctrl+Home/Ctrl+End for the very top and bottom; those keys are Obelus's and never reach the program. Drag to select what was printed, then Ctrl+c or Ctrl+Insert to copy it; with nothing selected, Ctrl+c goes to the program as usual. If the program uses the mouse itself (an editor, a process list), it gets the left button and the wheel; hold Shift to select anyway. Quitting while a program is running asks first, and once it ends the keys are Obelus's again.

02The agent's tools

Through ACP an agent can already read files and ask for permission, but it can't get at your notes. So Obelus gives it a few extra tools over MCP. The tools themselves never ask you anything: the agent is the one who asks, on a card, before it calls one.

ToolDoes
todo_listEvery note in this project: what it says, whether it's done, and where it points
todo_addAdd notes, at the top level or under another note (steps worked out in a conversation about a note go under that note). For things worth coming back to, not a summary of what the agent just did
todo_finishTick a note off. It only ticks, never deletes: a list of what you decided against is as useful as a list of what you never got to, and deleting a note is your call
todo_rewordChange the wording of a note. The only tool here that can lose something (notes aren't in git, and the page has no undo), so the agent has to ask first and show you both the old and the new wording

Three more: open_file opens a file at a line once you say yes (Alt+← takes you back); read_workflow tells the agent which workflow this project uses before it changes anything; and close_conversation closes the conversation once you say yes.

03Settings & themes

Two files

FileWhose
~/.config/obelus/config.tomlYours. open-settings saves to it as soon as you change anything
<project>/.obelus/config.tomlThe project's. It overrides yours, but only for the settings a project is allowed to set

No file means the defaults, and so does a line Obelus doesn't recognise: a typo should still leave you with a working editor, not an error message. The one exception is a file Obelus can't parse at all. Then it stops writing to that file, so it doesn't save over settings it couldn't read, tells you so, and carries on as soon as the file parses again.

It also tells you which line. A settings file that won't parse, a key binding that doesn't work, a setting the project isn't allowed to set, a theme with no file: each is marked on its own line, in the same list as the language server's errors, so Alt+e and Alt+[ Alt+] find them like any other problem.

Six settings a project can't set: agent, keys, agents, new_versions, conversation_days and read_only. All six are yours, not a downloaded repository's: which program gets started on your machine, where your keys are (a project could move quit somewhere you'd hit by accident), what an agent may do without asking (exactly what a hostile project would want to set), whether Obelus goes online to check for updates, how long your conversations are kept (a project could empty your list), and whether your own keys may edit files.

The settings

A few settings only apply to the window or only to the terminal. The settings page only shows the ones that apply to the version you're in, so you never change something and see nothing happen. The file keeps all of them, because the other version on the same machine reads it too.

Key Default What it is

Rebinding

Write only what you want to change: rebind one key and everything else keeps its default, including keys Obelus adds later. An empty string removes a binding. Use the command names from above, and write keys the way the screen shows them (case doesn't matter).

theme = "light"
wrap = true
blame_margin = false

[keys]
open-file = "Ctrl+o"
show-change = "Alt+g"
quit = ""            # taken away

Themes

dark and light are built in; choose-theme switches between themes instantly. Any .toml file in ~/.config/obelus/themes/ is also a theme, named after the file (omarchy.toml → omarchy). Every colour is optional: anything you leave out comes from the built-in theme yours is based on, so an old theme file keeps working when Obelus adds a colour.

contrib/omarchy/ in the repository is a template for omarchy: when you change your desktop theme, Obelus's colours follow. Obelus itself knows nothing about omarchy; the template just writes the theme file for you.

04Several windows

Obelus has no split panes, so it's normal to have several Obelus windows open at once: on one project, on different worktrees of it, next to your own shell. Here's what that means in practice.

  • All the worktrees of a repository share one set of notes. What one window writes shows up in the others by itself.
  • Two windows editing the same file don't erase each other: every change is made against what's on disk at that moment. Before saving, Obelus checks whether another window, an agent or a formatter changed the file since you opened it.
  • A conversation can be open in only one window at a time. That hold goes away when the window's process ends, so a crash never leaves a conversation stuck.
  • Change the settings file in one window, or by hand, and every window picks it up.
  • If the worktree a window is on is removed, from your shell or with git worktree remove, a page over the whole window says so. Enter lets go of everything that was open there (there is nowhere left to save it) and asks which project to open next; Ctrl+q quits.
  • In the worktree list (F2, then Tab), a tree next to the main checkout is shown by its own name, one inside it by the path down to it, and anything else by its full path. A tree deleted without telling git says Missing and can't be chosen.
  • Each window runs its own language server and its own agent. Three windows on one Rust project means three rust-analyzers.
