Obelus

符合我个人习惯的编辑器，agent 就在里面。

Obelus 是一个代码编辑器，在它自己的窗口里，或者在终端里。它不追求强大，而是围着一种干活方式长出来的——我的方式。你也这样干活的话，它对你也会顺手：agent 在自己的分支上改代码，你在被改的代码旁边读它改了什么，你不点头，什么都不会离开那个分支。

开始使用 看看它怎么走一遍 GitHub

01你是这样干活的吗

Obelus 假定的是某一种工作日。看看是不是你的。

  • 你同时推进好几个项目，同一个仓库也开着不止一个 worktree
  • 大部分代码是 agent 写的；你的活是读、判断、决定下一步做什么
  • 你有一份「接下来做什么」的清单，更希望它就在代码旁边，而不是在另一个应用里
  • 你宁可打开文件直接读，也不想先学一套模式：方向键、Ctrl+c、Ctrl+z
  • 你习惯开好几个窗口并排，让终端或者桌面去排布它们

大部分说中了，这一页剩下的就是 Obelus 为此做的事。如果你要的是最强大的编辑器，先看它不做什么。

02它为此做了什么

一条笔记，变成一个合进去的改动

agent 在自己的分支上干活；你读它改了什么、试一试、说可以了才走。你正在读的那份 checkout 一直不动，你也不用敲一条 git 命令。本页最上面那一屏，就是这样一天里的某一刻。

  1. 01

    从一条笔记开始。

    一行存疑的代码——在那一行上按 Alt+t，写一句话——或者一个不对着哪一行的计划，写在笔记页上（命令面板里的 todo）。不管哪种，它都进了这个项目的笔记，同一个仓库的每个 worktree 共用这一份。

  2. 02

    和 agent 把它聊清楚。

    在笔记上按 Alt+a，开一段关于它的对话，agent 会被告知笔记写的是什么。一起想要做成它需要什么；你同意的步骤写在这条笔记底下。

  3. 03

    它在自己的分支上改代码。

    动手之前，它开一个 worktree，分支按这次改动起名——放在 .worktree/ 底下，这个 workflow 新开的树都放在那里——先让它能编译、把测试跑一遍，这样之后测试挂了，就知道是这次改动的事。对话的标题行写着改动在哪个分支上。

  4. 04

    它告诉你去哪试，然后等着。

    它再跑一遍测试，告诉你目录和分支、跑了什么、结果是什么——而不是「应该没问题」——然后等你试过再说。F2 再按 Tab 就到那棵树的窗口；在那边，这次改动就是这个分支上最新的提交，在它写的某一行上按 F11 就能打开它。

  5. 05

    你没点头，什么都不会离开那个分支。

    你说试过了，它才问要不要先审一遍——能开一个干净的上下文就开——再把发现的问题按轻重列出来，让你勾要修哪些。然后问这次改动怎么回去：直接合并，开 pull request，还是先留着以后再说。

  6. 06

    pull request 它跟到底。

    它用 gh 开 PR，盯着 checks，哪个挂了说清楚为什么，你同意就修，全过了再合并。没有登录好的 gh，它就把分支推上去，把链接交给你。

  7. 07

    最后收拾干净，也是问过再做。

    合进去以后：你的 checkout 正好在它合进去的那个分支上的话，要不要跟上去——只做快进，别的不做——要不要删掉那个 worktree。笔记做完了：要不要打勾，要不要关掉这段对话。

上面每一个问题都是对话里的一张卡片，用你手上本来就按着的那几个键回答。没有哪一次推送、合并、删除或打勾，是因为 agent 觉得「该做了」。

这就是 feature-branch 这个 workflow，默认就开着，除非你设成 workflow = "none"——Ctrl+p → open-settings → Workflow——那样 agent 就按它自己的方式改，通常直接改在你正在读的那份 checkout 里。项目可以替自己选；不是 git 仓库的项目没有分支可开，agent 就在原地改。Obelus 自己不跑任何 git：每一条命令都是 agent 的。

每个 worktree 都只隔着一个键

Obelus 不分屏：想并排看两个文件，就是两个窗口。所以同一个项目上开着好几个、各在自己的 worktree 上，是常态。在窗口里，F2 有第二个 tab，按 Tab 过去：git 知道的这个仓库的每一个 worktree 都在里面，不管它在哪儿，有窗口开着的会标出来。选一个，开着它的那个窗口就跳到前面来，没开就新开一个。

只有 obg 列这些。去另一个地方，要么是启动一个 Obelus，要么是把一个带到前面来，而终端两样都做不到：它所在的窗口是终端的，你想在哪个终端里开新的 Obelus，Obelus 也没法知道。所以 ob 里没有这个 tab，switch-worktree 也是灰的。

  • 同一个仓库的每个 worktree 打开的是同一份笔记，另一个窗口写的东西会自己出现。
  • 两个窗口同时写，不会互相抹掉：每一次改动都以那一刻磁盘上的内容为准。
  • 一个对话同一时刻只在一个窗口里打开，占用随进程消失而消失——不存在「上次没退干净」。
  • 一个窗口底下的树被删掉，窗口留着，里面开着的东西也留着，只是项目变灰。

每条笔记都有自己的对话

Obelus 没有自己的模型。它通过 ACP（Agent Client Protocol）和你已经在用的 agent 说话；你还没有的话，它能从协议作者维护的注册表里装一个：F4，新建对话，进 agents 页。

  • 对话是打开的文档之一。离开它，明天回来，它还在你离开的地方。
  • 从笔记开的对话一直属于那条笔记；你改写了笔记，agent 会被告知改了什么。
  • agent 可以把下一步写在笔记底下、给某一步打勾、或者改写一条——每一件都先问过你。
  • 问题是一张卡片，不是一段话：上面是 agent 要做什么，下面是答案，Enter 作用于你所在的那一行。
  • 它请求做的改动显示在对话里；它已经做了的改动在文件里，和别的改动一样画在边栏上。

笔记记得自己指着哪儿

在一行上按 Alt+t，就起一条关于它的笔记；todo 打开全部。笔记可以对着某一行，也可以对着整个项目，还可以挂在另一条底下。它除了记行号，还记着写下时的那个提交，所以上周写的笔记，文件再怎么改，也还指着当初那一行。笔记放在 Obelus 自己的目录里、按项目存——所以每个 worktree 都共用，也永远不会进你的提交。

读改了什么

git

  • 边栏标出改了哪些行，和 git diff 说的是同一件事
  • 滚动条内侧是整份文件的改动地图
  • Alt+d 就地展开 / 收起一个 hunk，Alt+p / Alt+n 在改动之间走
  • 边栏显示这一行最后是谁改的（可关）
  • 文件的历史 F9、项目的历史 F10、这一行是哪个提交写的 F11；提交信息悬在文件上方，远端还没见过的提交有标记
  • 只读：Obelus 不碰你的仓库，也不替你跑 git

在窗口里，或者在终端里

  • obg 是窗口，ob 是终端——gvim 之于 vim 的那种关系，不是第二个程序：同一套网格、同一套视图、同一套键
  • 窗口是为了终端给不了的两件事。终端分不出 Ctrl+i 和 Tab、Ctrl+m 和 Enter、Ctrl+[ 和 Esc——各自都只有一个字节——而 Ctrl+Shift+X 大多数终端干脆什么都不发
  • 而且它用自己带的字体画，不用赌你装了哪一套：字形编译在二进制里，所以没有方框，也没有开关要找
  • 它自己画像素，所以光标和列表是移过去而不是跳过去，输入法正在拼的字也会先画在页面上

同一个文件，不止一种读法

  • markdown 排成文章（Ctrl+t）、日志排成列——按内容判断，不是按文件名
  • markdown 里的代码块、HTML 里的脚本，各按各自的语言上色
  • 长行按各自语言的规矩折：中文按字断，英文单词不会被拦腰切开，续行保持缩进
  • 还有那些寻常的：23 门语言、折叠、软换行

问代码

  • IDE 能回答的那些——名字在哪定义、谁调用它、它是什么、哪里有错——去问你本来就装着的语言服务器：rust-analyzer、gopls、clangd、pylsp 等
  • 找东西是一个界面、三个半径：本文件 F5、整个项目 F6、服务器认得的名字 F8——Alt+← 回到跳转开始的地方
  • 问题不只来自服务器：Obelus 自己读不懂的设置，会标在读不懂的那一行上，和服务器的问题在同一个列表里

没有模式的按键，在窗口里也在终端里

每个键什么时候按都是它字面上的意思——VS Code、Emacs 那样，不是 vim、helix 那样。功能键打开一样东西来看，Ctrl 对眼前的文件做点什么，Alt 问光标底下是什么。Ctrl+p 按名字找任何命令，Ctrl+k 列出眼前这个视图的所有键。完整的表在参考里。

03它不做什么

是故意的，不是还没来得及做。

  • 没有多光标、宏、片段。大块的改动现在是 agent 的活；这里有的，是读到一半顺手改一行需要的那些。
  • 不分屏。并排看两个文件就是两个窗口；终端或者窗口管理器排布得比编辑器从里面排得好。
  • 没有模式。没有 vim、helix 的键位，也没有打开它们的开关。
  • 自己不写 git。Obelus 只读 git、从不写。改动要去哪儿的时候，跑 git 的是 agent——而且先问过你。
  • 同一时刻只有一个 agent。两个就意味着每个问题都得先说是问哪个。
  • 没有自己的模型。它和你已经在用的 agent 说话。

如果上面哪一条正是你挑编辑器的理由，Obelus 不会适合你——这没关系，它本来就不是为此做的。

04设计理念

这些是做取舍时真正拿来对照的句子，大多是吃过一次亏之后才写下来的。

  1. 01

    合一种干活方式，而不是一张清单。

    一个功能在这里，是因为这种干活方式会用到它，而不是因为编辑器都该有。

  2. 02

    agent 做了什么，你看得见，也收得回。

    它写文件，是作为一次改动经过那个文件的，Ctrl+z 就能撤掉。它跑的命令撤不掉，所以命令按它真正跑的样子显示出来，输出全在，而让 agent 停下的那个键也会让命令停下。

  3. 03

    已经发生的改动在文件里；还在请求的改动在对话里。

    agent 改完一个文件，边栏已经画出了差别；在对话里再画一遍，就是同一件事说两遍。它请求做的事留在对话里，一直留着。

  4. 04

    你读着的文件被改写，是常态。

    agent 改了你开着的文件，格式化工具跑了，分支在你脚下换了。所以 Obelus 自己重读，不丢你的位置；文件没了就标上 [stale]，内容留在屏幕上。

05为什么写它

说实话：我是写给自己用的。每一个取舍先回答「我用着顺不顺手」，再回答「会不会有人因为缺某个功能而不用」——所以这一页说的习惯，是我的习惯。

vim 那套我一直不习惯。模式、hjkl、冒号命令——对习惯的人是肌肉记忆，对我是每次都要重新想一遍的东西。我想要的是打开就能读：方向键就是方向键，Ctrl+c 就是复制，不用先退出什么。

而且我干活的方式变了。大部分代码是一堆 claude code、codex 写的；我坐在屏幕前做的是读、确认、标出存疑的地方、决定下一步——还有一份我想放在代码旁边、而不是另一个应用里的 todo。终端里的编辑器都在比编辑器的清单。Obelus 也是编辑器，但在另一条线上：语法树、git 的时间线、语言服务器和 agent，按我干活的方式排好。

06上手

装它

一个 shell 一个脚本，你在哪个 shell 里就用哪个。两个都是取最新的 release，拿这次 release 自带的 SHA256SUMS 核对下载下来的东西，然后把 obg 放到 PATH 找得到的地方——在自己窗口里的那个 Obelus。

Linux 和 macOS

curl -fsSL https://raw.githubusercontent.com/obelus-editor/obelus/master/contrib/install.sh | sh

Windows，在 PowerShell 里

irm https://raw.githubusercontent.com/obelus-editor/obelus/master/contrib/install.ps1 | iex

连终端版一起装

ob 是另一个二进制，要点名才装。-s -- 后面的东西都交给脚本；管道进 iex 没地方放参数，所以 Windows 上先把脚本下下来。

curl -fsSL https://raw.githubusercontent.com/obelus-editor/obelus/master/contrib/install.sh | sh -s -- --bin both
irm https://raw.githubusercontent.com/obelus-editor/obelus/master/contrib/install.ps1 -OutFile install.ps1
.\install.ps1 -Binary both
  • --bin ob 是只装终端版，--dir 说放到哪儿，--help 列出其余的。
  • Releases 页上每个平台都有一份归档，另外还有 .deb、.rpm、AppImage 和 macOS 的 .app。
  • Windows 上脚本会把它的目录加进 PATH，并在开始菜单里建一个条目，-NoShortcut 让它不碰开始菜单。shell 脚本在目录还不在 PATH 上时，会告诉你该加哪一行；Linux 上它在 ~/.local/share 下，给装了的 obg 和 ob 各建一个 desktop entry（ob 的会在终端里打开）和一个图标，所有启动器都读它们——omarchy 菜单里的 Apps 也是；--no-desktop 让它不装这些。
  • -Uninstall 收回二进制和开始菜单的条目；目录里再没别的东西时，连目录和 PATH 里那一项一起收回。--uninstall 要带上安装时的那个 --dir，收回二进制、desktop entry 和图标，在 omarchy 上还有主题模板；PATH 它从来没改过，也就不碰。两边都不碰你的设置。
  • musl 上没有 obg：窗口要靠 dlopen 找 Vulkan、Wayland 和 X11，静态二进制做不到，脚本会直接说出来，然后装 ob。

从源码

只需要一套 stable Rust 工具链（edition 2024）。

git clone https://github.com/obelus-editor/obelus
cd obelus

# 装到 ~/.cargo/bin，命令叫 obg：在自己窗口里的 Obelus
cargo install --path crates/obelus-gui

# 装成 `ob`：同一个编辑器，跑在终端里
cargo install --path crates/obelus-cli

# 或者只构建：target/release/obg 和 target/release/ob
cargo build --release

另外值得装的

  • 一套 Nerd Font 补丁字体——文件名旁边、状态栏上的字形要靠它，这是终端里的事。默认就是关的，所以没装也不会出现方框。obg 不需要：这些字形编译在它的二进制里。
  • 你这门语言的 language server（Rust 就是 rust-analyzer）。没装也能读，只是没有定义跳转、诊断和大纲。
  • 一个说 ACP 的 agent。Obelus 自己能从注册表里装，见和 agent 对话。

跑起来

obg                  # 什么都不给：在当前目录打开欢迎页
obg src/main.rs      # 读一个文件——它所在的那个仓库就是项目
obg ../another-repo  # 给一个目录：它就是项目
ob src/main.rs       # 同一个文件，改在终端里读

头五分钟

  1. F1 打开文件。输入就是筛选，↑↓ 选，Enter 确认，Esc 取消。
  2. 不知道某个视图有哪些键？按 Ctrl+k。底下那行只列当下能用的，Ctrl+k 弹出全部（用不了的会灰掉）。
  3. Ctrl+p 是命令面板：记不住键的，都能按名字找到。
  4. 把光标放到一个改动上按 Alt+d：这个 hunk 会就地展开，改之前是什么样就写在那儿。
  5. 看到一行可疑的，Alt+t，写一句。它记在这个项目的笔记里，下次 todo 还能找回来。
  6. Ctrl+p → open-settings 调颜色、换行、tab 宽度这些；choose-theme 换主题。
  7. Ctrl+q 走人。

每个键、命令和设置都在参考里。
