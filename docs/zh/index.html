Obelus

一个终端里的代码阅读器。
它不希望你打字。

AI 时代，你读的每一行大多不是你写的。obelus（÷、†）是古代学者在手稿边上标记「此处存疑」的记号——一个读者在读的时候留下的记号。

01为什么写它

说实话：它首先是写给我自己用的。每一个取舍先回答的是「我用着顺不顺手」，而不是「会不会有人因为缺某个功能而不用」。

vim 那套用法我一直不习惯。模式、hjkl、冒号命令——它们对习惯的人来说是肌肉记忆，对我来说是每次进终端都要重新想一遍的东西。我想要的是：打开就能读，方向键就是方向键，ctrl+c 就是复制，不用先按 esc 想一想自己在哪个模式里。

另一半原因是这几年读代码的方式真的变了。AI 写走了很多行，我坐在终端前面做的事越来越偏向「读、确认、标出存疑的地方、问一下 agent」，而不是「敲」。终端里好用的编辑器不少，但它们都是编辑器：功能表按编辑器的清单展开——多光标、宏、补全、片段。我要的东西在另一条线上：语法树、git 的时间线、语言服务器，以及和 agent 的对话——全部围着「读」这一件事组织。

我平时是什么样子

现在用 AI 写代码，我经常同时推进好几个项目：开着一堆 claude code、codex，一个编辑器，外加一份 todo 用来计划下一步做什么。同一个仓库我也常常开很多个 worktree，各自完善不同的部分。Obelus 是照着这个样子长的：它不分屏，而是假定你同时开着好几个，并为此做了准备。

那份 todo 也是我把笔记做进 Obelus 的原因：计划下一步这件事发生在读代码的中间，而不是发生在另一个应用里。

02几个亮点

  • 每条笔记都能有自己的对话，明天回来它还在和 agent 对话 ›
  • agent 能读写你的笔记——但动手之前必须先问你和 agent 对话 ›
  • 上周写在某一行旁边的笔记，靠 git 还指着当初那一行笔记 ›
  • 一个仓库的几个 worktree 共用一份笔记，两个窗口同时记不会互相抹掉多窗口 ›
  • 同一个文件不止一种读法，也不止一种语言它能做什么 ›
  • 没有模式，键就是你在图形编辑器里已经会的那套按键 ›

03设计理念

这些不是事后总结的口号，是遇到每个取舍时反复拿来做决定的那几句话。大多是踩过一次才写下来的。

  1. 01

    读是主角，编辑是顺带的。

    叫它「编辑器」，它就会被按编辑器的清单去量：多光标？宏？片段？——那些它一个都不想要。有基本的编辑，是为了读到一半顺手改一行。

  2. 02

    不用先学一门方言。

    没有模式。方向键就是方向键，ctrl+c 就是复制，ctrl+z 就是撤销。你在图形编辑器里已经会的那套手感，在这里直接能用。

  3. 03

    不做分屏。

    想并排看两个文件？再开一个 Obelus 就行了。这不是「还没做」，是不会做。因此多开才是常态，Obelus 为这件事做了准备——见 多窗口、多 worktree。

  4. 04

    已经发生的改动在文件里；还在请求的改动在对话里。

    agent 改完的，就是工作区和上次提交的差别，边栏一直在画它；对话里再画一遍，就是同一件事的第二个说法。它正在请求做的改动才摆在对话里，而且事后留着。

  5. 05

    文件在你读的时候被改写，是常态。

    不是意外——agent 在改你正开着的文件，格式化工具在跑，分支在脚底下换。所以 Obelus 自己重读，不问你，位置也不丢；文件没了就标上 [stale]，内容仍然留在屏幕上。

04它能做什么

读一个文件

  • 语法高亮，15 门语言
  • 行号边栏、软换行、折叠（alt+f）
  • 长行折行按 Unicode 的断行规则：中文按字断，英文单词不会被拦腰切开；续行保持缩进，只有第一行有行号
  • 同一个文件不止一种读法：markdown 排成文章（ctrl+t）、日志排成列——按内容判断，不是按文件名
  • 同一个文件也不止一种语言：markdown 里的代码块、HTML 里的脚本，各按各自的语言上色

git

  • 边栏标出改了哪些行，和 git diff 说的是同一件事
  • 滚动条内侧是整份文件的改动地图
  • alt+d 就地展开 / 收起一个 hunk，alt+p / alt+n 在改动之间走
  • 边栏显示这一行最后是谁改的（可关）
  • 文件的历史 F9、项目的历史 F10、这一行是哪个提交写的 F11；提交信息悬在文件上方，远端还没见过的提交有标记
  • 只读：Obelus 不碰你的仓库，也不替你跑 git

语言服务器

  • 定义 F12、大纲 F7、符号搜索 F8
  • alt+enter 打开关于光标下这个名字的菜单：类型定义、实现、引用、调用关系
  • alt+h 悬停说明；鼠标停一会儿也行（时长可调，0 为关）
  • 诊断：全部 alt+e，上一个 / 下一个 alt+[ alt+]
  • 重命名 alt+r，code action alt+a，inlay hints（可关：关掉之后屏幕上的列就和文件里一模一样）
  • Obelus 认得的服务器：rust-analyzer、gopls、clangd、pylsp、typescript-language-server、bash-language-server、CSS / HTML / YAML

找东西

  • 一个界面，三个半径：本文件 F5、整个项目 F6、符号 F8
  • 文件、已打开的文档、主题、命令：四个列表，用法完全一样
  • 结果还在陆续出现的时候，列表不会自己跳动，并且会说自己「还在读」
  • alt+← / alt+→ 回到跳转之前的位置，以及再跳回来

05上手

装它

目前从源码构建。需要一套比较新的 Rust 工具链（edition 2024）。

git clone https://github.com/sunli829/obelus
cd obelus

# 装到 ~/.cargo/bin，命令叫 ob
cargo install --path crates/obelus-cli

# 或者只构建，二进制在 target/release/ob
cargo build --release

可选，但装了更好用：

  • 一套 Nerd Font 补丁字体——文件名旁边、状态栏上的字形要靠它。没有的话在设置里把 icons 关掉，屏幕上就不会出现方框。
  • 你这门语言的 language server（Rust 就是 rust-analyzer）。没装也能读，只是没有定义跳转、诊断和大纲。
  • 一个说 ACP 的 agent。Obelus 自己能从注册表里装，见下面。

跑起来

ob                   # 什么都不给：在当前目录打开欢迎页
ob src/main.rs       # 读一个文件——它所在的那个仓库就是项目
ob ../another-repo   # 给一个目录：它就是项目

头五分钟

  1. F1 打开文件。输入就是筛选，↑↓ 选，enter 确认，esc 取消。
  2. 不知道某个视图有哪些键？按 F1。底下那行只列当下能用的，F1 弹出全部（用不了的会灰掉）。
  3. ctrl+p 是命令面板：记不住键的，都能按名字找到。
  4. 把光标放到一个改动上按 alt+d：这个 hunk 会就地展开，改之前是什么样就写在那儿。
  5. 看到一行可疑的，alt+t，写一句。它记在这个项目的笔记里，下次 todo 还能找回来。
  6. ctrl+p → open-settings 调颜色、换行、tab 宽度这些；choose-theme 换主题。
  7. ctrl+q 走人。

三个家族，好记的地方在家族本身。这里列的是默认表——每个都能改，见 配置。

两排四个，正是它们在键盘上的样子。永远不带修饰键：同一个按法在不同终端上发出来的东西并不一样，所以带修饰的功能键是「这台机器上能用、换一台就不能」的绑定。

移动，和列表里

移动不是命令，所以它不在上面那些表里：方向键、PageUp/PageDown、Home/End（行首行尾）、ctrl+Home/ctrl+End（文件两端）。上下是按视觉行走的，所以换行之后它仍然是你看到的那一行。shift 从不命名任何命令，它只做一件事：扩展选区。

列表里（任何一个 picker、设置页、统计页、笔记页）：打字就是筛选，↑↓ 选，PageUp/PageDown 快速翻，Home/End 到两端，enter 作用于光标所在那一行，esc 取消，F1 列出全部的键。

08配置与主题

两个文件

文件是谁的
~/.config/obelus/config.toml你自己的。ctrl+p → open-settings 改任何一项都会立刻写回这里
<项目>/.obelus/config.toml这个项目的，盖在你的上面——但只盖它有权盖的那些项

文件不在、读不了、或者里面写错了，三种情况是同一个意思：用默认值。配置里有个笔误，你该得到的是一个照常开起来的 Obelus，而不是在本该是阅读器的地方得到一条错误信息。

项目不能设的三项：agent、keys、agents。一个下载来的项目不该决定你的机器上启动哪个程序；能改键的项目也就能把 quit 挪到你会误触的地方；而「agent 不用问就能做什么」正是一个陌生项目最想写的那一项。

能设的项

改键

写的是改动，不是整张表：你动了一个键，其余没说的仍然拿默认——以后 Obelus 加了新键，你也照样拿得到。空字符串表示「把这个键拿掉」，这也是一种决定。命令的名字就是上面那些。

theme = "light"
wrap = true
blame_margin = false

[keys]
open-file = "ctrl+o"
show-change = "alt+g"
quit = ""            # 把这个绑定拿掉

主题

内置 dark 和 light，choose-theme 切换，不重新解析文件。此外，~/.config/obelus/themes/ 下每个 .toml 就是一个主题，名字就是文件名（omarchy.toml → omarchy）。每个颜色都可以不写：没写的从它声明要盖在上面的那个内置主题来——所以以后 Obelus 多出一种颜色，你手上的旧文件不用改也仍然管用。

仓库里的 contrib/omarchy/ 是给 omarchy 的模板：桌面换一次主题，Obelus 的颜色跟着换。Obelus 自己对 omarchy 一无所知——那只是一个「有人帮你把文件写好」的办法。

09笔记

obelus 是学者在手稿边上标「此处存疑」的那个记号。笔记就是把那个记号写下来。

读到一半按 alt+t，笔记页打开，第一条就已经就着光标那一行起好了头；命令 todo 打开全部。这一页一直在被写：打开时光标就在里面，敲一个字母就是一个字母，enter 起下一条，shift+enter 在同一条里换行。把一条笔记当笔记来操作的键都在 alt 底下：打勾、跳到它说的那一行、挪位置、拿掉。底下那行列着当下能用的键，F1 给全部。

一条笔记可以是关于某一行的，也可以是关于整个项目的，两者都很正常：「这个缓存是错的」属于某一行，「把统计页接到搜索上」属于整个项目。它指着哪儿，写在它下面单独的一行；什么都没写的笔记不会被留下。笔记可以挂在另一条底下，缩进就是层级。

上周写的笔记，还指着当初那一行

行号会变。所以笔记记下的不只是行号，还有当时那个提交——重新找回位置这件事交给 git 去算，而不是让它指着后来挪进那一行的东西。

它们存在哪

在 Obelus 自己的目录里，按项目存，而不是按某一个 checkout 存。所以同一个仓库的几个 worktree 打开的是同一份清单；它们是你自己的笔记，不会进到项目的提交里去。

10和 agent 对话

Obelus 不实现任何人的模型，它只和你已经有的那个说话——用 ACP（Agent Client Protocol），和语言服务器一样的形状：另一个程序，走它自己的标准输入输出。

装一个

哪些 agent 存在不是 Obelus 说了算。协议的作者维护着一份注册表，Obelus 读它：四十来条，每条有名字、版本、说明和安装方式。ctrl+p → talk-to-agent（或 F4），在 agents 页里挑一个装。能画图的终端会直接显示每个 agent 自己的 logo，不能的显示一个字形。同一时刻只有一个 agent：两个就意味着每次提问都要先说「问哪个」，而你得记住这件事。

对话是一份文档

它就在 F2 的那份列表里。走开是「去了别处」，不是「关掉了」——回来的时候，说过的话都还在。enter 发送，alt+enter（终端支持的话 shift+enter 也行）换行。状态栏那一行是这个 agent 自己声明的会话选项——模式、模型、推理强度之类——就地走、就地改；shift+tab 一直是反着走的那一个。Obelus 一个字也不翻译：哪些选项存在是 agent 的事。

一场对话属于一条笔记

用 F4 开的对话不关于任何特定的事；从一条笔记开的，就是关于那条笔记的——而且一直是：明天回来，对话还在你离开的地方，因为说过的话由 agent 自己重放，Obelus 只需要记住哪个对话是关于哪条笔记的。

对话开始时，Obelus 会把这条笔记说了什么告诉 agent。你半夜把笔记改写了，下一条消息会带上改了什么——否则按协议，agent 没有任何办法知道周一告诉它的那段话周二已经变了。

在你说第一句话之前，Obelus 还会先说清楚它在跟谁说话：这个人正在终端里读代码，你说的话会落在他正读的文件旁边；凡是该由他决定的事，用提问的方式问，而不要在回复里写成 1) … 2) …——那样到他那里只是一段文字，屏幕上没有任何东西表示这是在等一个回答。

它问你的时候

问题是一张卡片，不是一个选择列表。卡片上方是它要做什么——那个工具调用本身，就画在对话里它该在的位置——下面是答案。走过某一行不等于选中它：输入框在答案下面，任何走到输入框的路都会经过它们，如果焦点走到哪儿就答到哪儿，那你路过时就把问题答了。enter 作用于你所在的那一行，这就是全部的规则。

它想改文件的时候

已经改完的：那就是工作区和上一次提交的差别，去文件里看——对话里只是一行 +12 -4。还没改、正在请求你同意的：那些行既不在文件里也不在上一次提交里，所以它们画在对话里，就画在那次调用底下，敞着；而且事后也留在那儿——这就是你以后翻回去确认「我当初同意了什么」的地方。画法和文件里展开的 hunk 一模一样，因为它们说的是同一件事。

Obelus 也把自己的笔记交给它

agent 用协议能读文件、能请求权限，但它没有办法说「我觉得那条笔记可以勾了」或者「这儿还有两条值得记下来」。MCP 是为这个开的门，Obelus 就是门后面应答的那一端。四个工具，全都不自己问你——要不要做，是 agent 自己去问，走它已经在说的那套协议。

工具做什么
todo_list这个项目的每一条笔记：说了什么、有没有勾、指着哪儿
todo_add写下新的笔记。写「有人会想回头看的东西」，而不是「我刚才干了什么」的总结
todo_finish勾掉一条。只勾，不删——「当初决定不做」的清单和「一直没顾上」的清单一样值钱，而删不删是你自己的事
todo_reword改写一条的措辞。四个里唯一会弄丢东西的一个（笔记不在 git 里，页面也没有撤销），所以它被要求先问你，并且把改前改后都摆给你看

11多窗口、多 worktree

Obelus 不分屏，所以「同一个项目上同时跑着好几个 Obelus」不是边缘情况，而是设计前提。下面这些是它为此给的保证。

一个仓库和它的 worktree 是同一个项目

你为同一个仓库开了三个 worktree，它们打开的是同一份笔记，也共用同一份「哪个对话正被人用着」。你开着三个 worktree，想回头看的本来就是一张清单，而不是三张。

两个窗口同时记笔记，不会互相抹掉

每一次改动都以磁盘上当下的内容为准，而不是以这个窗口开着的时候看到的那份为准。所以另一个窗口刚记下的东西不会因为你这边后保存就消失——而且中途被杀掉也不会留下半个文件。

一个对话同一时刻只能在一个 Obelus 里打开

agent 那边记着说过的话，而且一次只接一轮。两个窗口同时往同一个对话里提问，就是把两轮塞进一轮里去。所以对话是被占用的：别的窗口看得见它已经有人在用。占用随进程消失而消失——被 kill、崩掉、断电都一样，不用谁去清理，也不存在「上次没退干净所以现在打不开了」。

另一个窗口做的事，这边自己会出现

笔记页开着的时候，另一个窗口新写的笔记、新开的对话，会自己出现在这一页上，不用你先按点什么。

保存之前，先看一眼别人动过没有

另一个窗口、agent 或者格式化工具可能已经改过这个文件。这个问题是在你按下保存的那一刻去问磁盘的，而不是靠「刚才好像没收到通知」来猜。
