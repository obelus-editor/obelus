01按键与命令

没有模式，所以下面每个键什么时候按都是同一个意思——像 VS Code、Emacs，不像 vim、helix。按键分三类：功能键、Ctrl、Alt，记住每一类管什么，具体的键就好记了。这里是默认按键，每个都能改，见设置。

F1–F12：打开要看的东西

四个一组，跟键盘上的分组一样：F1–F4 打开要读的东西，F5–F8 是搜索，F9–F12 是 git 历史、跳转定义，以及 PR 和 issue。功能键都不带修饰键，因为 Shift+F5 这类组合在不同终端里发出来的东西不一样，在这台机器上能用，换一台就不行了。

键 命令 做什么
F1open-file在这棵树里挑一个文件打开
F2switch-document在已经打开的文档和 worktree 之间切换
F3open-changed-file打开一个上次提交之后改过的文件
F4choose-conversation和 agent 开一段新对话，或者接着聊以前的
F5search-file在正在读的这个文件里搜
F6search-project在整个项目里搜
F7show-outline这个文件定义的每个符号
F8search-symbols搜语言服务器知道的名字
F9show-file-history改过这个文件的每个提交
F10show-project-history项目的提交历史
F11go-to-definition光标下这个符号定义在哪
F12review-pull-request仓库里 open 的 PR 和 issue

还有两个不带修饰键的

Insert 是 toggle-replace：打的字会盖掉光标下的字，而不是插在前面，开着的时候状态行会写着 Replacing。Esc 取消选择，或者关掉最上面那个东西。

移动光标，以及在列表里

移动光标不算命令，所以不在上面的表里：方向键、PageUp/PageDown、Home/End（行首、行尾）、Ctrl+Home/Ctrl+End（文件开头、结尾）。上下是按屏幕上看到的行走的，长行折过来以后也一样。Shift 不对应任何命令，只用来扩大选区。

在列表里（各种选择列表、设置页、代码行数统计页）：打字筛选，↑↓ 选，PageUp/PageDown 翻页，Home/End 到头、到尾，Enter 选定当前这一行，Esc 取消，Ctrl+k 看全部按键。功能键在整屏的视图里也能按，会直接换成它对应的视图：在文件列表里按 F6 就换成搜索，F3 是文件列表的另一个 tab。

在对话里

Enter 发送，Alt+Enter 换行（终端支持的话 Shift+Enter 也行）。在关于笔记的对话里，输入框空着时按 →，会填进一句建议的开场白。Shift+Tab 切换 agent 自己的模式，显示在最底下那一行。Esc 让 agent 停下，它正在跑的命令也一起停。Alt+t 跳到这段对话所属的笔记。agent 问你问题时是一张卡片：↑↓ 选，Enter 回答。

在笔记页

笔记页随时可以直接打字：Enter 开始下一条，Alt+Enter 或 Shift+Enter 在一条里面换行。Tab 把一条挪到上一条底下，Shift+Tab 再挪出来。其余操作笔记的键都在 Alt 上：Alt+Space 打勾，Alt+o 跳到它指着的那一行，Alt+a 打开它的对话，Alt+↑Alt+↓ 调整顺序，Alt+← 删掉。

在终端里

open-terminal 在项目目录里打开你的 shell，它是一个单独的文档；agent 要你登录时，登录程序也在这样的终端里跑。程序在跑的时候，按键都交给程序，Esc、Ctrl+c 也是。Obelus 只留下功能键、Ctrl+p、退出用的 Ctrl+q、粘贴用的 Ctrl+v 或 Shift+Insert，以及关掉终端的 Ctrl+w（程序还在跑的话会先问一句）。

想往回看已经滚走的输出：滚轮，PageUp/PageDown 一次一屏，Ctrl+Home/Ctrl+End 到最前、最后，这几个键归 Obelus，不发给程序。拖动鼠标能选中输出的文字，Ctrl+c 或 Ctrl+Insert 复制；没选中东西时，Ctrl+c 照常发给程序。程序自己要用鼠标时（比如编辑器、进程列表），左键和滚轮交给它，按住 Shift 还能自己选。程序在跑时退出 Obelus 会先问一句，程序结束后按键都还给 Obelus。

02给 agent 的工具

通过 ACP，agent 本来就能读文件、请求许可，但碰不到你的笔记。所以 Obelus 通过 MCP 另外给它几个工具。工具本身不会问你什么：要问的是 agent，在调用之前用一张卡片问。

工具做什么
todo_list这个项目的所有笔记：写了什么、勾没勾、指着哪儿
todo_add加笔记，放在最外层，或者挂在某条笔记底下（关于某条笔记的对话里商量出的步骤，就挂在那条底下）。记的是以后值得回头看的事，不是「刚才干了什么」的总结
todo_finish给一条打勾。只打勾，不删除：「决定不做」的清单和「还没顾上」的清单一样有用，删不删由你决定
todo_reword改一条笔记的文字。四个工具里只有它会丢东西（笔记不在 git 里，笔记页也没有撤销），所以 agent 必须先问你，并把改前、改后都给你看

另外三个：open_file 在你同意后把一个文件打开到某一行（Alt+← 回到原处）；read_workflow 在 agent 动手改之前，告诉它这个项目用的是哪套工作流；close_conversation 在你同意后关掉这段对话。

03设置与主题

两个文件

文件是谁的
~/.config/obelus/config.toml你自己的。在 Ctrl+p → open-settings 里改了什么，都会马上存到这里
<项目>/.obelus/config.toml这个项目的。它会覆盖你的设置，但只能覆盖项目有权设的那些项

没有文件就用默认值；有一行 Obelus 不认识，那一项也用默认值——配置里一个笔误，不该让编辑器打不开。只有一种情况例外：整个文件解析不了。这时 Obelus 不再往这个文件里写，免得把它没读懂的设置覆盖掉；它会告诉你，等文件能解析了再自动恢复。

它还会告诉你是哪一行的问题。配置文件解析不了、某个键绑不上、项目设了无权设的项、主题名字找不到对应的文件——都会标在出问题的那一行上，和语言服务器报的错放在同一个列表里，所以 Alt+e 和 Alt+[ Alt+] 照样能找到它们。

项目不能设的六项：agent、keys、agents、new_versions、conversation_days、read_only。这六项都该你说了算，不该由一个下载来的仓库定：你的机器上启动哪个程序；按键放在哪（能改键的项目就能把 quit 挪到你会误按的地方）；agent 不问你就能做什么（这正是不怀好意的项目最想改的）；Obelus 要不要联网检查新版本；对话保留多久（项目能借此清空你的对话列表）；以及你自己的键能不能改文件。

能设的项

有几项只对窗口版或只对终端版有效。设置页只列出对你当前这一版有效的，免得你改了却看不到任何变化；文件里则全都留着，因为同一台机器上的另一版也读这个文件。

键 默认 是什么
theme"dark"Obelus 用哪套颜色画
iconsfalse只对终端版。显不显示 Nerd Font 图标——没装补丁字体的话会显示成方框。窗口版自带图标，不看这一项
wrapfalse太长的行要不要折到下一行显示。默认关，一行就是一行
blame_margintrue边栏上显示每一行最后是谁改的
tab_width4一个 tab 画多宽。2、4 或 8
fonts[]只对窗口版。用哪些字体，按你写的顺序，前一个没有某个字时才用后一个。留空就用系统默认的等宽字体
animationtrue只对窗口版。光标和列表是滑过去还是直接跳过去。关掉就直接跳
font_size14只对窗口版。字号，单位 point。终端版用的是终端自己的字号
hover_delay400鼠标在一个词上停多少毫秒，才显示它是什么；0 表示只在按键时显示
read_onlyfalse你自己的按键不能改文件：在文件里打字、粘贴、剪切、撤销和改行的命令都不起作用。agent 的修改照样写进去，保存照样能存；给 agent 发消息、搜索框、笔记这些输入框不算文件，照常能打字
format_on_savefalse保存前让语言服务器格式化一遍。默认关：没人要求就格式化，会把一个只是打开来看的文件改掉，而你要到看 diff 时才发现
code_actions_on_savefalse保存前执行服务器提供的整文件修复（比如整理 import）。默认关，理由同上
inlay_hintstrue显示服务器推导出的类型和参数名。它们不在文件里，关掉后每一列都回到文件里真实的位置
diagnosticstrue在光标所在的行下面显示服务器的报错文字。出错的地方无论如何都有下划线，这一项管的只是那段文字，它会多占一行
ignored_filesfalse文件列表里也显示项目忽略掉的文件
hidden_filesfalse文件列表里也显示隐藏文件：名字以点开头的，以及 Windows 上设了隐藏属性的
new_versionstrue每天去 GitHub 查一次有没有新版本，有的话在欢迎页上说一声
workflow"feature-branch"agent 怎么改这个项目。feature-branch：在自己的 worktree 和分支上改；in-place：步骤一样，但直接改你正在看的代码；none：按 agent 自己的习惯来。不是 git 仓库的项目没有分支可开，agent 就直接改。见工作流。项目可以设
conversation_days30不挂在笔记上的对话，最后一条消息之后多少天被忘掉；0 表示永远不忘。agent 那边对话还在，只是 Obelus 找不回去了，事后把天数调大也找不回来。挂在笔记上的对话跟着笔记走；有窗口正开着的对话不会被忘

改键

只写你要改的：改了一个键，其他的照旧用默认，以后 Obelus 加的新键你也能用上。空字符串表示去掉这个键。命令名就是上面那些；键的写法和屏幕上显示的一样，不区分大小写。

theme = "light"
wrap = true
blame_margin = false

[keys]
open-file = "Ctrl+o"
show-change = "Alt+g"
quit = ""            # 把这个绑定拿掉

主题

内置 dark 和 light 两套，choose-theme 切换，马上生效。另外，~/.config/obelus/themes/ 下的每个 .toml 文件都是一个主题，名字就是文件名（omarchy.toml → omarchy）。每个颜色都可以不写，没写的沿用它所基于的内置主题——所以以后 Obelus 多了新颜色，你的旧主题文件不用改也能用。

仓库里的 contrib/omarchy/ 是给 omarchy 的模板：桌面换主题时，Obelus 的颜色跟着换。Obelus 本身不知道 omarchy 的存在，模板只是替你把主题文件写好。

04多个窗口

Obelus 不分屏，所以同时开好几个 Obelus 窗口是常态：同一个项目开几个，不同的 worktree 各开一个，旁边还有你自己的 shell。实际用起来是这样的：

  • 同一个仓库的所有 worktree 共用一份笔记，一个窗口里写的，别的窗口自己就会出现。
  • 两个窗口改同一个文件，不会互相抹掉：每次改动都以那一刻磁盘上的内容为准。保存之前，Obelus 会先检查你打开之后，别的窗口、agent 或格式化工具有没有改过这个文件。
  • 一段对话同时只能在一个窗口里打开。占用跟着进程走，窗口崩了占用也就没了，不会出现对话「卡住打不开」。
  • 在一个窗口里改了设置，或者直接改了设置文件，所有窗口都会跟着变。
  • 窗口所在的 worktree 被删掉了（在 shell 里删的，或者 git worktree remove），整个窗口会弹出一页说明这件事。按 Enter 放下这个项目里打开的一切（已经没有地方可存了），再选下一个要打开的项目；按 Ctrl+q 退出。
  • worktree 列表里（按 F2 再按 Tab），和主 checkout 并排的 worktree 显示它自己的名字，在主 checkout 里面的显示往下的路径，别处的显示完整路径。没通过 git 就被删掉的 worktree 显示 Missing，选不了。
  • 每个窗口有自己的语言服务器和自己的 agent。同一个 Rust 项目开三个窗口，就是三个 rust-analyzer。
